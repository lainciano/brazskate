> **STATUS: APROVADO — implementado na mesma sessão via plano de execução.**

## Contexto e motivação

I3 (texto do termo) foi resolvida em 25/07/2026 — ver D19 em
`02-DECISOES.md`. O texto vigente vive em `docs/termo-responsabilidade.md`,
com um aviso de proveniência explícito: o advogado deu OK informal, sem
parecer formal ainda; se a análise formal alterar redação, o arquivo precisa
ser atualizado antes de coletar aceite real de um competidor.

Esta sub-etapa entrega:

1. Fonte única `data/termo.ts`, no molde de `data/faq.ts`/`data/evento.ts`.
2. Rota `/termo` no vocabulário visual do site.
3. Exportação em PDF com a identidade visual completa (fonte Anton, cores da
   marca, logo) — decisão do Lain, contra a alternativa mais barata de CSS de
   impressão. O custo é assumido e mitigado por import dinâmico.

## Escopo

**Entra:**
- `data/termo.ts` — array `as const` com os dois blocos (maior de idade,
  autorização de responsável por menor), cada um com cláusulas
  `{ titulo, texto }`. Conteúdo transcrito de `docs/termo-responsabilidade.md`.
- `app/termo/page.tsx` — página estática, registro concreto (leitura longa).
- `/termo` em `app/sitemap.ts`.
- Botão "Baixar PDF" (`components/termo-pdf-botao.tsx`, cliente) com estados
  idle → gerando → erro.
- `lib/termo-pdf.ts` — monta o PDF a partir do mesmo array de `data/termo.ts`.
- `public/fonts/Anton-Regular.ttf` + `public/fonts/OFL.txt` (licença
  obrigatória para redistribuir a fonte).
- `lib/anton-base64.ts` — módulo isolado com o TTF em base64, para só entrar
  no bundle via import dinâmico.
- Link para `/termo` no `Footer`.

**Não entra:**
- Assinatura certificada ou serviço de assinatura eletrônica — D19 já fechou
  isso: aceite por checkbox no formulário externo, papel no credenciamento.
- Página `/inscricao` ou religar o CTA "Quero competir" — depende do
  formulário Tally existir (V1.4 é insumo, não consumidor).
- CSS de impressão como alternativa ao PDF gerado — descartado nesta sessão
  em favor de embutir a fonte de marca.

## Fonte única — `data/termo.ts`

```ts
export const termo = {
  versaoTexto: "25/07/2026",
  blocos: [
    { id: "maior", titulo: "Para maior de idade (18+)", clausulas: [...] },
    { id: "menor", titulo: "Para menor de idade (até 17 anos)", clausulas: [...] },
  ],
} as const;
export type TermoBloco = (typeof termo)["blocos"][number];
```

D20: nenhuma cláusula cita patins, bicicleta ou outro equipamento não-skate.
Página e PDF renderizam do mesmo array — editar uma cláusula reflete nos dois.

## Página `/termo`

Esqueleto de página secundária igual a `app/patrocinio/page.tsx`: `Header`,
hero curto em registro asfalto com `Grao`, `Rasgo` na transição, corpo em
registro concreto com `SectionHeader` por bloco, `Footer`. Um único `h1`;
cada bloco (`termo.blocos`) em `h2`; cada cláusula em `h3`. Texto corrido
dentro de `max-w-6xl`, medida confortável (~65ch, §2.2 do design).

## Geração do PDF

**Import dinâmico no clique (D19):**

```ts
const [{ jsPDF }, { antonBase64 }] = await Promise.all([
  import("jspdf"),
  import("@/lib/anton-base64"),
]);
```

Nada de `jspdf` nem da fonte entra no bundle inicial — só carrega quando o
usuário clica "Baixar PDF".

**Fonte Anton:** TTF baixado de Google Fonts (v27, licença OFL-1.1, arquivo
de licença vendorizado em `public/fonts/OFL.txt`) — o woff2 servido por
`next/font/google` não é aceito pelo `addFont` do jsPDF, que exige TTF em
base64. `lib/anton-base64.ts` isola esse payload (~174KB em base64) num
módulo próprio para garantir que só vem pelo import dinâmico.

**Identidade visual no PDF** (tokens de `05-DESIGN.md` §2.1):
- `tinta` `#191314` — texto principal, cabeçalho.
- `creme` `#f5ebe4` — fundo de faixas/realces.
- `vermelho-600` `#9c4242` — acento em títulos.
- Anton nos títulos (cabeçalho do documento + título de cada bloco) — nunca
  no corpo das cláusulas, mesma regra do site (§2.2: Anton nunca abaixo de
  2rem nem em texto corrido). Corpo em fonte padrão do jsPDF (Helvetica).
- Logo: `public/logo-completa.png` no cabeçalho, buscado via `fetch` em
  runtime (mesma origem, site estático) e embutido com `addImage` — evita um
  segundo blob base64 versionado no repo.

**Layout A4** (210×297mm): margens de 20mm, quebra de página entre os dois
blocos, linha de assinatura + data ao final de cada bloco, rodapé com
`termo.versaoTexto` em todas as páginas. Cor só em título/acento — nunca como
único portador de informação, para permanecer legível impresso em preto e
branco.

## Componente do botão

`components/termo-pdf-botao.tsx` (`"use client"`) usa `Botao` variante
secundária, sem `href` (ação, não navegação — §3.1). Estados via hook
próprio se a lógica crescer (`hooks/use-termo-pdf.ts`, padrão de
`hooks/use-copiar.ts`): idle → "Gerando PDF…" (com `aria-live="polite"`) →
idle; erro cai para um estado que expõe mensagem e mantém o botão utilizável
para tentar de novo.

## Critério de pronto

- `pnpm lint` + `pnpm typecheck` + `pnpm build` limpos; `/termo` aparece como
  rota estática.
- Bundle inicial não cresce — jsPDF e a fonte só aparecem no chunk carregado
  no clique (checar aba Network).
- PDF abre em A4, com Anton nos títulos, cores da marca, logo no cabeçalho,
  legível em preto e branco.
- Editar uma cláusula em `data/termo.ts` reflete na página e no PDF.
- `/termo` navegável por teclado; botão de PDF com foco visível e estado
  "gerando" anunciado.
